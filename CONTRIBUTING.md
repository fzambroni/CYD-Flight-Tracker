# Contributing

Contributions are welcome. By submitting a contribution, you agree that it may be distributed under the MIT License.

1. Open an issue describing the problem or proposed change.
2. Fork the repository and create a focused branch.
3. Do not commit secrets, personal locations, device identifiers, or generated build files.
4. Keep the supported hardware profile unchanged unless the contribution explicitly adds and documents a new variant.
5. Validate Home Assistant YAML and compile the ESPHome YAML.
6. Test populated, empty, and missing-field flight data where relevant.
7. Update documentation and `CHANGELOG.md` for user-visible changes.
8. Submit a pull request with hardware, ESPHome/Home Assistant versions, tests performed, and screenshots when UI changes are involved.

Bug reports should include the board marking/display variant, relevant software versions, expected and observed behavior, and sanitized logs. Remove Wi-Fi names, IP addresses, API keys, precise locations, and other private information.
